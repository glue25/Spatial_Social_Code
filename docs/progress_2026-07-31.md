# Progress Update: EnactToM E0 and Repository Cleanup

日期：2026-07-31

## 1. 本轮里程碑

Spatial Social Code 已从 formulation 进入第一个全量可执行实验：

```text
EnactToM task JSON + PDDL
→ query-independent oracle Spatial–Social Code
→ golden trajectory reducer
→ first-order message interventions
→ target sensitivity + non-target invariance
```

实现入口：

- `spatial_social_code/enacttom.py`
- `scripts/run_enacttom_e0.py`
- `tests/test_enacttom.py`

结果：

- `reports/enacttom_e0_oracle_results.json`（运行时生成，Git 忽略）
- `reports/enacttom_e0_oracle_results.md`

## 2. 实验范围

| 项目 | 数量 |
|---|---:|
| Task entries | 300 |
| Unique task IDs | 289 |
| Physical goals | 1,013 |
| First-order probe cases | 317 |
| Higher-order probe cases | 303（仅诊断） |

E0 覆盖公开 golden trajectory 中出现的全部动作类型：

- Navigate：2,782；
- Pick：649；
- Open：293；
- Place：649；
- Wait：1,526。

## 3. 主要结果

- 986/1,013 physical goals 可由保存的 golden trajectory 重放，goal-level replay rate 为 97.33%。
- 291/300 task entries 完成全部物理目标。
- 152 个一阶信息非对称案例可执行消息删除实验。
- 其中 71 个案例还存在合法的替代接收者，可执行重定向实验。
- 所有已执行案例的 oracle delivery、target sensitivity 和 non-target invariance 均为 100%。

这些 100% 是确定性 reducer 的语义单元测试结果，不是模型性能。

## 4. 数据诊断

E0 没有遇到未知或不可解析的 golden action，但发现：

1. 9 个 task entries 的保存轨迹只有 Navigate/Wait，没有 effectful action，因此无法达到其保存的 planner literals。
2. 76 个任务中的 83 个 golden navigation steps，按静态 PDDL room mapping 解析后进入了 acting agent 的 restricted room。

第二项可能是静态元数据、planner projection 与 Habitat runtime 语义之间的差异，必须在 Linux/Habitat 环境复核后才能判断是否属于 benchmark 错误。

## 5. 明确边界

- 公开 golden trajectory 不包含 communication actions。
- E0 的消息是由 supported first-order probes 和已观察物理事实构造的 oracle intervention。
- E0 不声称恢复了原始通信轨迹。
- 二阶、三阶知识目前只统计，不进入干预得分。
- 下一科学步骤是信息匹配的 Memory vs. Agent-indexed Interaction Code 推理实验，而不是直接下载大规模视频。
